# Video Generation (Gemini Omni Flash)

Reference for how `backend/routers/video.py` generates videos. The Veo preview models were
shut down by Google (they now return `404 ... use models/gemini-omni-1.1-flash ... Interactions API`);
the only video model is **`gemini-omni-1.1-flash`**, called through the Interactions API
(`client.interactions`, `google-genai` 2.28).

Official docs: https://ai.google.dev/gemini-api/docs/omni

## Job flow

1. `POST /api/video/generate` (or `/animate`) validates the request, then calls
   `interactions.create(..., background=True, store=True)`. Google answers in ~2 s with an
   interaction id (`v1_...`), which is stored in `video_jobs.operation_id`. The job id returned
   to the client is our own UUID.
2. The frontend polls `GET /api/video/status?jobId=...` every 10 s. Under a per-job lock the
   backend calls `interactions.get(id)`:
   - `in_progress` / `queued`: job stays `processing`.
   - `completed` with a video: the MP4 is decoded (inline base64; `uri` delivery falls back to the
     Files API), first/last frames are extracted, the video and thumbnail are saved to the media
     store, the user's video quota is charged **once** and the job becomes `completed`.
   - `completed` without a video: job `failed` ("No video was returned ... possibly filtered"),
     including the model's text reply if there is one. No quota is charged.
   - `failed` / `cancelled` / `incomplete` / `budget_exceeded`: job `failed` with the API's error text.
   - Network/5xx errors while polling: HTTP 502, the job stays `processing` and the next poll retries.
3. Finished and failed jobs are answered from the database without contacting Google.

The video client is created with **retries disabled** (`utils/gemini.get_video_client`): the
Interactions SDK otherwise retries timeouts/429/5xx, which could start and bill a second video.

On startup (`main.py` lifespan → `routers.video.recover_video_jobs`) unfinished jobs that can never
complete are marked `failed`: jobs for models no longer in the registry (old Veo jobs), jobs without
an interaction id, and jobs older than one hour. Recent Omni jobs are resumed by the next poll.

## Request mapping

| API field (camelCase) | Omni request |
|---|---|
| `prompt` | text input (the user's prompt comes first) |
| `negativePrompt` | appended to the prompt as `Avoid: ...` (Omni has no negative-prompt field) |
| `firstFrame` | 1st image input; the prompt gets "image 1 is the first frame of the video" |
| `lastFrame` | next image input; "image N is the last frame of the video" |
| `referenceImages` (max 3) | following image inputs; "images N-M are references for subjects, characters and style (not frames)" |
| `aspectRatio` | `response_format.aspect_ratio`: `16:9` (default) or `9:16` |
| `resolution` | `response_format.resolution`: `360p`, `720p` (default), `1080p`, `4k` (1080p/4k are upscaled) |
| `durationSeconds` | `response_format.duration` as `"<n>s"`; the API accepts 3-10 s, the UI offers 4/6/8/10, default 8 |

Images are sent as `{"type": "image", "data": <base64>, "mime_type": ...}` items followed by one
`{"type": "text", ...}` item. Frames and reference images may be combined; Omni infers each image's
role from the prompt, so the backend adds the role sentence shown above. `/animate` uses
`sourceImages[0]` as the first frame and up to three further images as references.

Invalid values are rejected with HTTP 400 before anything is sent to Google (unknown model,
unsupported aspect ratio/resolution, duration outside 3-10 s, more than 3 reference images, invalid
base64). Requests Google rejects (policy, validation) also return 400 with Google's message; no job
is created and no quota is charged.

Not supported by Omni: system instructions, temperature, negative-prompt field, audio references.
Audio is generated by default. All videos carry a SynthID watermark.

## Capabilities and pricing

The source of truth is `_MODEL_REGISTRY` in `backend/utils/config.py` (served at `GET /api/config`);
the UI controls (resolutions, aspect ratios, durations, image inputs, negative prompt) are driven by
these capabilities.

Billing is per output token ($17.50 per 1M video tokens):

| Resolution | Tokens per second | ≈ Price per second | 8 s clip |
|---|---|---|---|
| 360p | ~1,930 (measured) | ~$0.034 | ~$0.27 |
| 720p | 5,792 (pricing page) | ~$0.10 | ~$0.81 |
| 1080p / 4k | not published (upscaled from 720p) | assume ≥ 720p | |

The registry shows `$0.10 per second (720p)` and `pricePerVideo = $0.80` (default 8 s clip).

Measured (Oct 2026, 360p, 4 s, background mode): ~24 s until `completed`, 640×360 at 24 fps,
4.0 s, 0.4-0.7 MB MP4.

## Limits and restrictions

- Images of recognizable real people are not supported; in the EEA, Switzerland and the UK also
  no images of minors. Prompts violating the usage policies are blocked.
- Editing/extending uploaded videos is not available in the EEA (this app does not use it).
- English prompts work best; other languages are untested by Google.
- Admins can enable/disable the model in the admin UI or via `ENABLED_VIDEO_MODELS` /
  `DISABLED_VIDEO_MODELS`; stale Veo ids in old configuration are ignored.

## Troubleshooting

- **400 "The video model rejected the request"**: Google's validation or policy message is included.
- **Job `failed` with "No video was returned"**: the output was filtered; rephrase or use other images.
- **Job `failed` with "no longer available"**: an old Veo job, failed at startup; start a new video.
- **Status returns 502**: Google was briefly unreachable; the frontend keeps polling.
